**Date:** 2026-07-23

## What I built

### D2/D5 — pooled forecasting and a water-balance experiment

I finished the global cross-sensor rung that trains one delta-target model across five soil probes. The runner now loads YAML rather than constructing experiment settings in Python, only uses declared features, and reports fleet-level median and worst-fold skill.

I also completed a small weather-correction model around persistence. It fits soil-moisture change from forecast-window ET₀ and precipitation, can gate corrections to rainy windows, use robust regression, and shrink back toward persistence using only recent training evidence. This stays an active experiment—not discarded—but it is not the served model yet.

An adversarial evaluation pass found a subtle problem in the shared walk-forward harness. At horizon `h`, the final `h-1` training labels occur after the first test prediction's decision time. I added a purge parameter to the D5 harness, applied `h-1` purging to target-time-aligned D2 models—including the pooled evaluator—and added regression tests. This is exactly why the evaluation layer needs independent review.

### D3 — label-free vegetation-index screening

The supervised CNN still needs labeled stress/pest imagery. Instead of inventing labels, I built a useful interim product:

- windowed per-block raster distributions (count, coverage, mean, standard deviation, quantiles, IQR, low-tail fraction);
- same-acquisition NDVI/NDRE concern scores;
- deterministic block ranks, coverage filtering, and index-disagreement flags;
- a typed YAML config and runner.

The implementation reads each polygon window rather than loading 4 GB orthomosaics. I verified that both real 2026-06-01 NDVI and NDRE files return HTTP 206 byte ranges and open through GDAL. An adversarial review then caught a real geospatial bug: the first run divided valid pixels by each polygon window's bounding-box area rather than its polygon-interior pixels, unfairly rejecting irregular blocks. That 30/9 split and its H6/L ranking are superseded. The corrected coverage and accepted-only ranking logic now has regression tests. A corrected authenticated range-backed rerun was externally terminated before writing a replacement artifact, so no current real-data block rank is claimed. These outputs remain field-inspection priorities, never diagnoses.

### D6 — local irrigation API

`GET /irrigation/forecast` now serves the D2 champion: persistence plus the fixed 25.0 threshold. The response includes the mapped sensor, observation time, four horizon forecasts, reading age, quality status, and explanation. Unknown blocks return 404; missing readings return 503; stale readings suppress the recommendation.

The real local Cc request returned 200 and correctly refused to advise from a stale snapshot. The final container smoke test reproduced that behavior from the non-root Docker image.

## Results

The corrected pooled GBT rerun confirms both signal and instability:

- Fleet skill: **−45.1% at 6 h**, **−52.2% at 12 h**, **+33.0% at 24 h**, **+30.2% at 48 h**.
- Fleet worst-fold skill remains negative at every horizon, including **−4.2% at 24 h** and **−35.5% at 48 h**.

These pooled gains also use realized future-weather features, so they are
oracle-assisted upper bounds rather than evidence that pooling alone works
operationally. The fleet row is a row-weighted micro-average of correlated
sensor-hours, not independent replication; per-device and per-fold behavior
remain the decision evidence. Pooled ridge loses fleet-wide at every horizon.
Alert prevalence is high enough that precision/recall alone cannot establish
transition-detection value.

The water-balance oracle-weather experiment is more conservative:

- Corrected 48 h aggregate skill is positive on all five probes: **+3.5% to +11.2%**.
- Every probe still has a negative worst fold: approximately **−9.7% to −34.1%**.
- At LS-4/48 h, recall is **0.908**, versus **0.912** for persistence.

These are realized-future-weather results, so they are an upper bound. They justify keeping water balance as an active candidate for archived-forecast and new-holdout evaluation, not promoting it today.

This post records the focused gates available at drafting time. The repository-wide final gate is rerun after the notebook/report integration rather than frozen to an intermediate test count.

## Decisions

[ADR-0003](../adr/0003-track-priority.md) still governs promotion: complexity must beat persistence robustly, not only in pooled MAE or one rain event. Persistence remains the served fallback. Water balance remains active experimental work.
